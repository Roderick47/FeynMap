# P2.3b — downstream answer fidelity and shipping gate

P2.3a established that an opt-in symbol/evidence delivery policy can retain
more task-bearing semantic evidence than the earlier file-oriented P2.1
policy. It deliberately did **not** show that a downstream language model
answers questions more correctly, makes fewer unsupported claims, or costs
less end-to-end. P2.3b measures that missing layer without changing the
legacy default.

## Pre-registered fresh source and answer oracle

Before exporting any model-facing context or collecting any answer, P2.3b
freezes `experiments/p2_3b_answer_manifest.json` and twelve source files under
`experiments/fixtures/p2_3b_fulfillment/`. The corpus is separate from P2.2
stockroom and P2.3a dispatch development cases. It includes Python
implementation, regression tests, a migration, JavaScript cross-module
behavior, explicitly absent refund behavior, and one deliberately nonexistent
`issue_refund` identifier.

The frozen answer contract contains six questions. Five are answerable from
source evidence; one requires `need_more_context`. Source-authored required
claims and contradicted/unsupported trap phrases exist only in the scorer
index. Search, packing, and model packets never receive those labels.

Both the unchanged legacy packer and opt-in `symbol_evidence` packer consume
the exact same S2 activation for each question. Tight (1600/12/12) and
standard (3200/24/24) contexts are exported for structural comparison; only
the standard budget is used for downstream model answers in this checkpoint.

## Grounded answer protocol

The downstream answer is strict JSON:

```json
{
  "status": "answer | need_more_context",
  "claims": [
    {
      "text": "one atomic factual statement",
      "evidence_nodes": ["delivered node ids"],
      "evidence_edges": ["delivered edge ids"]
    }
  ],
  "missing_identifiers": []
}
```

The model must answer only from the supplied FeynMap envelope. Every factual
claim requires a citation to actually delivered evidence. A missing explicit
identifier or `delivery_sufficient=false` should cause `need_more_context`
rather than invented behavior.

The deterministic scorer records required-claim recall, invalid or missing
citations, pre-registered unsupported-claim traps, unnecessary abstention,
correct request-more-context behavior, FeynMap context estimates, and actual
provider input/output tokens only when a provider reports them. The lexical
unsupported-claim detector is explicitly **not** exhaustive semantic fact
checking.

## Shipping discipline

A downstream run is eligible to influence the default only if it is blind to
the source-authored answer oracle and satisfies the frozen fidelity and cost
gates. An interactive development answer generated by a model/session that
has already seen the fixture or oracle must record
`eligible_for_shipping_decision=false`; even perfect scores keep
`symbol_evidence` opt-in.

P2.3b remains separate from the sealed S7 agent-repair corpus. S7 is the
broader task-level generalization test and is not consumed here.
